# Java SE 复习笔记仓库

需求已确认；第 13 模块样稿已按反馈修订，用户已确认修订后的风格。

GitHub spec：[#1](https://github.com/Q1Xuan/java-se/issues/1)（ready-for-agent）。

## Problem Statement

现有 Java 学习资料分散在课件、老师字幕、练习和其他文件中，复习时需要反复查找。已有笔记术语重、复述多、完整业务代码过长，不容易快速找回知识点；部分“源码已核对、代码已验证”的说法也缺少实际记录。

用户希望整理一套准备开源的中文 Java SE 笔记。内容横跨现有课程的 27 个模块，需要先统一标准，再通过多个 session 持续完成，避免每次重新解释需求或丢失进度。

## Solution

沿用课程模块及顺序，每个模块内部按知识主题整理。面向已经学过、需要复习的读者，用简单中文写清规则、区别和必要语法，难懂处保留短代码。

先用第 13 模块“嵌套类、局部类与匿名类”制作样稿。资料核对、知识清单编写和检查完成后，由用户确认风格，再从第 01 模块按顺序推广。通过 spec、ticket 和进度记录保存约定与接续位置。

未来 GitHub 仓库公开新笔记、必要示例及项目文档；原始课件、字幕、源码下载链接和旧笔记留在本地。

## Implementation Decisions

### 范围与组织

- 采用现有课程的 27 个模块及原有顺序，不重新编排整套知识体系。JavaFX 和框架相关内容保留在原模块中。
- 模块内部按知识主题整理，不逐节复述课程。模块编号保持稳定，中文简称可以用于导航。
- 每个模块先采用一份 Markdown 知识清单；确实过长时再拆分主题。总入口展示模块导航及完成状态。
- 必要短代码优先内嵌在笔记中；确实需要独立保存的示例再单独提供，不强制建立 Java 工程。
- 跨模块知识采用简短提示和链接，避免重复展开。安装、IDE 等模块保留必要操作说明，省去逐次点击记录。

### 写作标准

- 面向学后复习。按需要说明“是什么、规则、写法、区别”，不要求每个主题套同一组小标题。
- 使用简单、准确的中文，专业名词首次出现时附一句白话解释。先写结论，只有帮助理解时才补原因。
- 每条主要表达一个知识点。同一个规则采用一个足够说明问题的例子，不提供多套完整业务实现。
- 分类和层级优先用 Mermaid 图表达，图中标明分类依据；语法优先用一行表达式或短代码展示。必要限定紧邻图或代码，避免将规则集中堆成大段文字。
- 涉及访问、作用域或对象关联的规则，用紧邻规则的简单示例展示具体对象、操作及结果；代码中的关键行和错误写法标注含义或原因，不能仅用抽象文字概括，也不能让读者自行推断文字对应哪一行。每个示例只承担相关知识点，不先用长篇文字重复代码。其他主题也按内容选择图、代码、表格或短文字。
- 短代码的省略范围应清楚；错误示例明确标注失败原因。练习提炼知识点，省去完整汉堡店、播放列表和员工管理程序。
- 不规定固定字数、知识点数量或代码行数，以覆盖完整、表达简洁为准。表格只作简短对比，复杂条件拆成条目。
- 主线省去课程开场白、夸张标题、操作复述、无关底层细节和面试题扩展。相同知识点不在总览、正文和易错点中重复展开。

### 资料与事实核对

- 先登记本模块实际存在的课件、字幕、练习、源码和其他资料，再逐项阅读、按主题归并并检查覆盖。
- 旧笔记只作线索，不能替代原始资料。只含下载链接的文本不视为已经读取的源码。
- 图片形式的代码和表格也要查看原页；不能仅凭提取出的正文认定课件已经完整处理。
- 资料缺失或无法读取时，记录原因、影响及剩余问题；不受影响的内容继续整理。
- 资料矛盾、规则可疑或版本相关时，查对应版本的官方文档，保存结论与来源。先核实课程使用的版本，再选择代码验证环境。
- 区分课程内容、帮助理解的必要补充和未确认问题。公开内容用自己的话整理，示例围绕知识点编写。

### 第 13 模块样稿范围

- 四种形式的分类与区别：静态嵌套类、成员内部类、局部类、匿名类。
- 静态嵌套类和成员内部类的声明、创建、外部成员访问，以及内部类与外部对象的关联。
- 内外成员同名时的访问方式。
- 局部类的声明位置、可用范围和使用外部变量的限制。
- 匿名类的声明与创建、继承或实现关系、构造相关限制。
- 局部变量不再重新赋值的要求，以及变量重新赋值和对象修改的区别。
- 课程涉及的局部类型、静态成员版本规则、比较器及不同实现方式的必要区别。
- 汉堡、播放列表和员工排序练习分别体现的知识点。
- 编译器生成字段和自动类名等实现细节不进入主线；有助于理解且经过核实的内容最多用短注说明。

### 执行与接续

- 样稿依次完成资料核对、编写、检查、用户确认四个任务。用户确认风格后，再完善公开仓库入口并推广其他模块。
- 后续模块按原顺序从第 01 模块开始，跳过已完成的第 13 模块；开始某模块时再展开资料核对、整理、检查三个任务。
- ticket 记录目标、依赖、交付和可检查的验收条件。状态区分待开始、进行中、待用户确认、完成和受阻。
- 每次 session 记录已处理的具体资料或主题、实际检查结果、剩余问题和下一步。持久记录不依赖临时提取文件或聊天上下文。
- 等待用户确认样稿时，保留相应状态；经过的时间不能代替确认。影响准确性的问题未解决前，不标记模块完成。
- 公开文件包括新笔记、必要示例和项目文档；原始课件、字幕、下载链接和旧笔记继续留在本地。

## Testing Decisions

### 验收入口

沿用已确认的“模块知识清单”作为主要验收入口：读者能否按模块找到知识、读懂规则、理解必要区别并正确使用示例。资料覆盖表和针对性代码检查为这个结果提供证据，不另造应用接口或测试框架。

### 检查内容

- **完整性**：逐项对照已读资料，知识点应能定位到清单；未保留的内容有简短处理说明，缺失资料及影响有记录。
- **可复习性**：检查分类是否适合用图、语法和规则是否可由短代码直观展示、解释是否紧邻示例，以及大段文字和重复是否已消除；以第 13 模块修订后经用户确认的风格作为后续依据。
- **代码行为**：选择关键创建语法、访问规则和局部变量限制等片段，验证正确用法能编译、错误用法按预期失败。确实需要展示运行行为时，再执行运行检查。
- **版本与事实**：核实有疑问的规则和版本差异，保存官方依据；编译检查只支持编译结论，不能写成已完成运行验证。
- **阅读与导航**：检查模块顺序、目录链接、状态标记、Markdown 代码块和表格是否正常。
- **公开内容**：检查待公开文件范围，确保没有夹入原始资料、下载链接和旧笔记。
- **接续能力**：进度记录应让下一 session 找到当前任务、已完成范围、未解决问题和下一个动作，不需要重新访谈。

### 测试原则与已有做法

- 检查面向读者能看到的内容和示例行为；不测试提取脚本内部结构、标题精确措辞或其他实现细节。
- 当前已有 Markdown 相对链接、代码围栏及 27 个模块编号完整性的轻量检查，可继续沿用。
- 当前没有已经建立的 Java 示例测试套件或完成样稿；不宣称存在此类先例。
- 第 13 模块先执行上述验收，其他模块复用相同原则，按实际知识补充有意义的检查。
- 不为纯文字调整增加测试框架，不给每条简单知识点机械配测试。

## Out of Scope

- 从零教学的长篇教程、课程逐字稿、完整业务项目和面试题库。
- 脱离课程范围大规模补充底层机制，或为了压缩篇幅省略关键规则。
- 重新划分课程模块、改变模块顺序，或把 JavaFX 等课程内容另行迁出。
- 在第 13 模块风格确认前，批量编写其他模块或一次性展开全部详细 ticket。
- 覆盖或删除旧笔记、公开原始课件字幕及源码下载链接。
- 为笔记搭建网站、应用、数据库、API 或自动化测试平台。
- 笔记内容的正式首发及许可证选择。任务跟踪所需的建仓库、标签配置和 spec issue 登记另行执行。
